# 人猫搭档 AIGC 项目 V1.7 落地实施测试验收方案

> 版本：V1.7  
> 整理时间：2026-07-02  
> 关联文档：`人猫搭档_AIGC项目修改意见整理.md`  
> 目标：把 V1.6 的修改意见落成可实现、可测试、可验收的生成流水线方案。

---

## 1. 结论

V1.7 不继续堆 Prompt 字段，而是建设一条稳定的内容生成流水线：

```text
最小入参
→ 故事规划 story_plan
→ 逐张分镜 frame_plan[]
→ 逐张文案 copy_plan[]
→ 逐张生成 Prompt prompt_plan[]
→ 顺序生成图片
→ 逐张验收 qa_result[]
→ 失败返工 retake_prompt
```

核心目标是让“人猫连续故事图”从一次性碰运气生成，改成可拆解、可检查、可返工的生产流程。

## 4. 核心数据结构

### 4.1 story_plan

用于描述整组内容的统一目标。

```json
{
  "story_id": "delivery_first_day_001",
  "story_title": "第一天送外卖",
  "platform": "抖音竖屏",
  "ratio": "9:16",
  "image_count": 6,
  "continuous_story": true,
  "story_template": "外卖跑单故事",
  "mood_curve": ["紧张", "小心", "专注", "进入状态", "有点慌", "放松"],
  "anchor_frame_index": 1,
  "text_render_mode": "生成空白气泡 + 后期叠字图层"
}
```

### 4.2 frame_plan[]

每张图只推进一个明确剧情动作。

```json
{
  "frame_index": 1,
  "main_action": "接到第一单，准备出发",
  "continuity_from_previous": "首张锚点图，无上一张",
  "visual_evidence": ["手机订单页", "电动车", "前车篮里的猫", "后外卖箱"],
  "character_emotion": "新手紧张但认真",
  "cat_state": "坐在前车篮里看镜头",
  "camera": "第三人称正面中景",
  "in_image_storyboard": false,
  "role": "anchor"
}
```

### 4.3 copy_plan[]

文案必须和每张分镜一一对应。

```json
{
  "frame_index": 1,
  "title": "第一单来了",
  "girl_bubble": "我先确认下",
  "cat_bubble": "要出发了吗",
  "narration": "第一天跑单，先稳住",
  "comment_prompt": "你第一单会紧张吗",
  "text_position": {
    "title": "顶部标题区",
    "girl_bubble": "人物右上方",
    "cat_bubble": "猫咪左上方",
    "comment_prompt": "底部字幕区"
  }
}
```

### 4.4 prompt_plan[]

第 1 张和后续图片必须使用不同生成策略。

```json
{
  "frame_index": 2,
  "generation_type": "continuation",
  "required_references": [
    "原始人物身份参考图",
    "原始猫咪身份参考图",
    "第1张锚点图",
    "上一张成图"
  ],
  "positive_prompt": "生成第2张：检查猫背带和装备...",
  "negative_prompt": "不要换衣服，不要换车，不要换猫，不要生成拼图，不要直接生成中文乱码文字"
}
```

### 4.5 qa_result[]

每张图生成后必须输出验收结果。

```json
{
  "frame_index": 2,
  "passed": false,
  "failed_items": ["道具连续性", "视觉证据不足"],
  "reason": "猫背带贴片变化明显，检查装备动作不清楚",
  "retake_prompt": "请基于第1张锚点图和上一张成图重新生成第2张..."
}
```

## 5. 实施阶段

### M1：入参和示例落地

目标：先让输入稳定。

交付物：

```text
minimal_input_schema.json 更新
外卖连续故事示例 JSON
居家治愈故事示例 JSON
```

验收标准：

| 验收项 | 通过标准 |
|---|---|
| 必填字段完整 | 缺少 `image_count`、`continuous_story`、`story_template` 等字段时能提示 |
| 默认值合理 | 未填写时默认 9:16、空白气泡后期叠字、分镜关闭 |
| 示例可解析 | 示例 JSON 能被脚本读取，无语法错误 |

### M2：文本流水线生成

目标：不生成图片前，先生成完整文字产物。

交付物：

```text
story_plan
frame_plan[]
copy_plan[]
prompt_plan[]
```

验收标准：

| 验收项 | 通过标准 |
|---|---|
| 分镜数量正确 | `frame_plan.length == image_count` |
| 每张动作唯一 | 每个 `main_action` 只表达一个动作 |
| 视觉证据完整 | 每张 `visual_evidence` 至少 2 项 |
| 文案完整 | 每张都有标题、女生台词、猫咪台词、评论引导 |
| Prompt 可用 | 每张都有正向和反向提示词 |

### M3：顺序生成策略落地

目标：明确第 1 张和第 2-N 张的参考图规则。

交付物：

```text
第1张锚点图 Prompt
第2-N张续图 Prompt
引用关系说明
```

验收标准：

| 张数 | 必须引用 |
|---:|---|
| 第 1 张 | 身份参考图、猫参考图、场景母版图 |
| 第 2 张 | 身份参考图、猫参考图、第 1 张锚点图 |
| 第 3-N 张 | 身份参考图、猫参考图、第 1 张锚点图、上一张成图 |

### M4：验收和返工落地

目标：生成后能判断是否失败，并输出可执行返工 Prompt。

交付物：

```text
qa_result[]
retake_prompt
失败原因说明
```

验收标准：

| 验收项 | 通过标准 |
|---|---|
| 可识别失败项 | 能标记剧情、连续性、气泡、文案、镜头等失败类型 |
| 可生成返工 Prompt | 每个失败项都有明确修复方向 |
| 不通过不进入下一张 | 连续故事模式下，当前张失败应先返工 |

### M5：真实图片测试

目标：用实际生成图验证流程。

测试集：

```text
外卖新手跑单 6 张
居家治愈故事 5 张
非连续同主题变体 3 张
```

验收标准：

```text
外卖 6 张能看出完整故事
居家 5 张能保持同一套服装和情绪
非连续模式不会强制套用上一张成图
```

## 7. 图片验收标准

### 7.1 整组验收

| 验收项 | 通过标准 |
|---|---|
| 故事完整 | 6 张图能看出起因、过程、结果 |
| 主角一致 | 女生脸、眼镜、发型稳定 |
| 猫咪一致 | 白色银渐层猫稳定，不换品种 |
| 服装一致 | 马甲、白 T、深色裤子不乱变 |
| 道具一致 | 电动车、前篮、外卖箱、猫背带连续 |
| 情绪推进 | 紧张 → 小心 → 专注 → 忙碌 → 有点慌 → 放松 |
| 镜头变化 | 至少 3 种景别或视角 |
| 平台适配 | 9:16，顶部和底部留安全区 |

### 7.2 单张验收

| 验收项 | 通过标准 |
|---|---|
| 单张动作清楚 | 不看文字也知道本张在做什么 |
| 视觉证据明确 | 有订单页、店门、外卖袋、楼栋等关键证据 |
| 气泡可用 | 气泡不挡脸，不挡猫，不挡关键动作 |
| 文案可落地 | 标题、女生台词、猫咪台词可直接叠字 |
| 构图不重复 | 不连续出现几乎相同的构图 |

## 8. 返工规则

### 8.1 返工触发条件

出现以下任一情况，必须返工：

```text
人物明显变脸
猫咪换品种或脸型明显变化
服装、车、前篮、外卖箱、猫背带不连续
当前图看不出剧情动作
气泡遮挡人脸、猫脸或关键动作
图片变成拼图、九宫格或多宫格
中文直接生成乱码
```

### 8.2 返工 Prompt 模板

```text
请基于第 1 张锚点图和上一张成图重新生成第 {frame_index} 张。

必须保持：
- 同一个年轻女生
- 同一只白色银渐层猫
- 同一套米色外卖马甲、白 T、深色裤子
- 同一辆浅色电动车
- 同一黑色网格前车篮
- 同一浅色后外卖箱
- 同一米色猫背带

本张只表达一个动作：
{main_action}

画面必须出现这些视觉证据：
{visual_evidence}

镜头改为：
{camera}

保留空白气泡，后期叠字，不要直接生成中文。
不要拼图，不要九宫格，不要漫画框。
```

## 9. 验收流程

```text
1. 读取输入 JSON
2. 校验 schema
3. 生成 story_plan
4. 人工确认 story_plan
5. 生成 frame_plan 和 copy_plan
6. 人工确认分镜和文案
7. 生成 prompt_plan
8. 生成第 1 张锚点图
9. 验收第 1 张
10. 通过后生成第 2 张
11. 逐张验收，失败先返工
12. 全部通过后输出发布清单
```

## 12. 风险与控制

| 风险 | 控制方式 |
|---|---|
| 模型忽略细节 | 用锚点图 + 上一张成图 + 当前分镜约束 |
| 中文生成乱码 | 默认空白气泡 + 后期叠字 |
| 连续故事变散图 | 生成前必须先确认 frame_plan |
| 构图重复 | 镜头节奏写入 frame_plan |
| 返工不可控 | 每个失败项生成独立 retake_prompt |

## 14. 执行结论

V1.7 的第一目标不是直接提升单张图质量，而是把生成过程变成可控流程。

先完成 M1-M4 的文本流水线，再进入 M5 图片实测。只有当分镜、文案、Prompt、验收和返工全部可追踪后，连续故事图才具备稳定复用的基础。
