# 通用剧情连载系统_沉淀复用实施方案

## 1. 目标

基于当前项目已经验证过的 AIGC 连载生产方法，沉淀一套可迁移到新剧情、新角色、新世界观、新画风的通用连载系统。

本方案只保留系统能力，不保留当前“人猫搭档”IP 内容。

## 2. 总原则

| 原则 | 说明 |
|---|---|
| 保留方法，不保留 IP | 连载流水线、锚点图、QA、批量生成、入口配置等能力全部保留；人猫角色、外卖故事、居家故事、银渐层猫等内容全部舍弃。 |
| 先结构化，再出图 | 先生成 story/frame/copy/prompt/qa/retake 等文本产物，人工检查后再进入图片生成。 |
| 先锚点，再连续 | 第 1 张先生成身份与风格锚点，第 2-N 张按顺序承接，不并行生成整组图。 |
| 通用字段优先 | 新项目优先复用字段结构，而不是复用字段值。 |
| 专属内容隔离 | 项目专属角色、风格、场景、负面词必须单独维护，避免污染通用系统。 |

## 3. 保留与舍弃清单

| 模块 | 处理结论 | 新项目落地方式 |
|---|---|---|
| 连载流水线 | 强制保留 | 保留 `story_plan / frame_plan / copy_plan / prompt_plan / qa_result / retake_prompt` 六类产物。 |
| 锚点图机制 | 强制保留 | 第 1 张做身份、服装、画风、道具锚点；后续图片引用锚点和上一张成图。 |
| 批量生成工具 | 强制保留 | 作为通用工具能力沉淀，支持多集、多任务、多剧情批量生成 Prompt 任务。 |
| 入口配置页 | 强制保留 | 改造成通用连载入口，允许选择剧情模板、张数、比例、互动、文字策略、锁定策略。 |
| 情绪曲线 | 保留 | 作为 `mood_curve` 情绪推进字段，字段保留，具体情绪词按新剧情重写。 |
| Negative Prompt | 保留并拆分 | 拆为“通用负面词”和“项目专属负面词”。 |
| 视觉基因表格式 | 保留 | 改造成“新角色 / 新世界观设定表模板”。 |
| QA 验收与返工 | 强制保留 | 保留通用验收框架，新增新题材专属验收项。 |
| 气泡与后期叠字策略 | 强制保留 | 默认使用空白气泡 + 后期叠字，降低中文乱码风险。 |
| 跨会话身份锁定方法 | 强制保留 | 保留参考图上传顺序、优先级、母版图机制；替换全部参考图内容。 |
| 场景 / 动作资产目录结构 | 保留结构 | 可沿用目录组织方式，内容全部替换为新剧情资产。 |
| 人猫角色设定 | 舍弃 | 不迁移女生、猫、眼镜、白色银渐层、互印 T 恤等设定。 |
| 外卖 / 居家故事模板 | 舍弃内容，保留机制 | 删除外卖和居家模板内容，保留“故事模板”机制。 |
| 人猫母版图 / 参考图 | 舍弃 | 新项目重新建立身份参考图、风格母版图、场景母版图。 |

## 4. 通用连载流水线

```text
最小入参
-> story_plan.json
-> frame_plan.json
-> copy_plan.json
-> prompt_plan.json
-> qa_result.json
-> retake_prompt.json
-> prompt_task.md
```

### 4.1 story_plan

用于定义整组连载的故事级信息。

| 字段 | 说明 |
|---|---|
| story_id | 连载或单集 ID。 |
| story_title | 本组剧情标题。 |
| story_template | 当前使用的剧情模板。 |
| story_outline | 本次故事从哪里开始、如何推进、在哪里结束。 |
| platform | 发布平台，例如通用、抖音竖屏、小红书图文。 |
| ratio | 图片比例，例如 9:16、4:3。 |
| image_count | 本组图片数量。 |
| continuous_story | 是否连续剧情。 |
| mood_curve | 情绪推进曲线。 |
| anchor_frame_index | 锚点图序号，默认第 1 张。 |

### 4.2 frame_plan

用于定义每张图的镜头、动作和承接关系。

| 字段 | 说明 |
|---|---|
| frame_index | 当前第几张。 |
| main_action | 当前画面只推进一个核心动作。 |
| continuity_from_previous | 和上一张的承接关系。 |
| visual_evidence | 画面里必须出现的视觉证据。 |
| character_emotion | 当前情绪状态。 |
| subject_state | 主体状态，可按新项目替换为角色、载具、道具、环境状态。 |
| camera | 镜头角度。 |
| role | anchor / continuation / variant。 |
| source_scene | 来源场景。 |

### 4.3 copy_plan

用于定义标题、旁白、角色台词和互动引导。

| 字段 | 说明 |
|---|---|
| frame_index | 当前第几张。 |
| title | 标题，建议短句。 |
| narration | 旁白或字幕。 |
| character_lines | 角色台词列表，不绑定固定角色名。 |
| comment_prompt | 评论区或互动引导。 |
| text_position | 标题、气泡、字幕的安全区建议。 |

### 4.4 prompt_plan

用于定义每张图的生成 Prompt 和参考图规则。

| 字段 | 说明 |
|---|---|
| frame_index | 当前第几张。 |
| generation_type | anchor / continuation / variant。 |
| required_references | 本张必须上传的参考图。 |
| reference_rule | 引用锚点图、上一张成图、母版图的规则。 |
| positive_prompt | 正向 Prompt。 |
| negative_prompt | 通用负面词 + 项目专属负面词。 |

### 4.5 qa_result

用于记录每张图是否通过验收。

| 字段 | 说明 |
|---|---|
| frame_index | 当前第几张。 |
| status | 待检查 / 通过 / 条件通过 / 不通过。 |
| failed_items | 失败项。 |
| reason | 失败原因。 |
| next_action | 入库、后期修、返工、废弃。 |

### 4.6 retake_prompt

用于把失败项转成可执行返工 Prompt。

| 字段 | 说明 |
|---|---|
| frame_index | 当前第几张。 |
| trigger | 触发返工的失败项。 |
| retake_prompt | 本张返工提示词。 |
| references_to_keep | 返工时必须继续上传的参考图。 |

## 5. 锚点图与连续生成规则

### 5.1 生成顺序

| 顺序 | 操作 | 目的 |
|---:|---|---|
| 1 | 上传身份参考图 + 风格参考图 + 当前场景母版图，生成第 1 张 | 锁定角色、画风、服装、关键道具、世界观气质。 |
| 2 | 上传身份参考图 + 第 1 张锚点图 + 第 2 张场景参考 | 承接锚点，推进剧情。 |
| 3-N | 上传身份参考图 + 第 1 张锚点图 + 上一张成图 + 当前场景参考 | 保持身份、画风、道具、时间线连续。 |

### 5.2 禁止行为

| 禁止项 | 原因 |
|---|---|
| 一次性并行生成整组图 | 容易退化成同主题散图。 |
| 第 2-N 张不带上一张成图 | 容易丢失剧情承接和道具状态。 |
| 每张重新设计服装和画风 | 破坏连载一致性。 |
| 把完整故事塞进补充说明 | 会导致脚本无法稳定拆分剧情、分镜和文案。 |

## 6. 通用连载入口配置

入口配置页应保留为通用连载入口，不再绑定具体 IP。

| 配置项 | 是否保留 | 说明 |
|---|---|---|
| 常用配置模板 | 保留 | 用于保存不同题材、平台、张数、文字策略组合。 |
| 故事情节 | 保留 | 填写本次剧情主线。 |
| 补充说明 | 保留 | 填写额外限制、禁忌项、返工要求。 |
| 图片比例 | 保留 | 支持 9:16、4:3 等。 |
| 平台 | 保留 | 支持通用、抖音竖屏、小红书图文等。 |
| 生成张数 | 保留 | 控制 frame/copy/prompt 数量一致。 |
| 连续情节 | 保留 | 控制是否启用锚点图和顺序承接。 |
| 剧情模板 | 保留并重写 | 删除人猫相关模板，新增新剧情模板。 |
| 情绪曲线 | 保留 | 作为剧情节奏控制字段。 |
| 气泡模式 | 保留 | 支持无、单角色、多角色、旁白标题等。 |
| 文字落地模式 | 保留 | 默认空白气泡 + 后期叠字。 |
| 观众互动 | 保留 | 支持评论引导、提问互动、投票选择等。 |
| 当前图内分镜 | 保留 | 默认关闭，仅特殊画面开启。 |

## 7. Negative Prompt 拆分规范

### 7.1 通用负面词

适用于所有项目，主要处理图片生成常见问题。

```text
different person, inconsistent identity, inconsistent style, cartoon, anime, painting, 3d render, plastic skin, over beautified face, exaggerated expression, distorted face, wrong hair, deformed body, extra fingers, missing fingers, extra arms, extra legs, broken hands, twisted limbs, blurry face, low resolution, watermark, messy text, gibberish text, logo distortion, bad anatomy, unrealistic lighting, overexposed, underexposed
```

### 7.2 项目专属负面词

每个新项目单独维护，不写进通用负面词。

| 类型 | 示例 |
|---|---|
| 角色禁忌 | 不要改变主角年龄感、发型、体型、肤色、标志性服装。 |
| 世界观禁忌 | 不要出现不属于当前世界观的科技、建筑、道具、符号。 |
| 风格禁忌 | 不要偏离目标画风，例如不要写实化、不要卡通化、不要赛博化。 |
| 平台禁忌 | 不要生成水印、乱码文字、广告标识、遮挡主体的贴纸。 |

## 9. 情绪曲线字段规范

情绪曲线不绑定具体题材，只描述每张图的情绪推进。

| 字段 | 说明 |
|---|---|
| mood_curve | 数组长度建议等于 `image_count`。 |
| frame_emotion | 每张图从 `mood_curve` 中取一个情绪状态。 |
| emotional_progression | 用于说明从开场到结尾的情绪变化逻辑。 |

### 9.1 示例

```json
{
  "mood_curve": ["疑惑", "试探", "紧张", "失控", "反转", "余味"],
  "emotional_progression": "从日常异常开始，逐步进入紧张，再用反转收束。"
}
```

## 10. QA 验收框架

### 10.1 通用验收项

| 验收项 | 通过标准 |
|---|---|
| 角色一致 | 看起来是同一个角色或同一组角色。 |
| 风格一致 | 多张图放一起像同一套连载。 |
| 场景合理 | 场景符合当前世界观。 |
| 道具连续 | 道具状态随剧情推进，不凭空消失或回退。 |
| 动作清楚 | 每张图只推进一个核心动作。 |
| 情绪推进 | 情绪曲线能被画面看出来。 |
| 文字安全 | 气泡、标题、字幕不遮挡主体，不出现乱码。 |
| 平台适配 | 关键主体不被裁切，顶部和底部安全区合理。 |

### 10.2 项目专属验收项

新项目必须补充以下内容：

| 验收类型 | 需要填写 |
|---|---|
| 角色专属验收 | 主角必须保留哪些视觉特征。 |
| 世界观专属验收 | 哪些元素一旦出现就算偏题。 |
| 风格专属验收 | 哪些画风偏移必须返工。 |
| 剧情专属验收 | 哪些关键动作或道具状态必须出现。 |

## 12. 后续实施优先级

| 优先级 | 事项 | 说明 |
|---:|---|---|
| P0 | 新建通用规范文档 | 本文档即为第一步。 |
| P0 | 抽离人猫专属配置 | 将角色、猫、外卖、居家内容从通用能力中剥离。 |
| P0 | 新建新项目视觉基因表 | 先定义新角色和新世界观，再生成 Prompt。 |
| P1 | 改造 Schema | 把 `story_template`、角色台词、场景枚举改成通用结构。 |
| P1 | 拆分 Negative Prompt | 建立 common/project 两份负面词。 |
| P1 | 改造入口页 | 做成通用连载入口。 |
| P2 | 改造批量工具 | 支持多集、多模板、多项目批量生成。 |
| P2 | 建立新项目 QA 模板 | 补齐题材专属验收项和返工 Prompt。 |

## 13. 明确不迁移内容

以下内容不得进入新项目通用层：

- 人猫搭档项目名。
- 年轻女生、圆框眼镜、深色长发等角色设定。
- 白色银渐层猫、猫咪视觉基因、猫咪台词等设定。
- 外卖跑单故事。
- 居家治愈故事。
- 沙发绿植、外卖车、外卖箱、楼道送餐等专属场景。
- 人猫母版图、身份参考图、旧项目可用图。
- 任何旧 IP 的专属文案、台词、标题和互动梗。

## 14. 最终结论

本次沉淀的核心不是“复用一套人猫项目”，而是复用一套可持续生产剧情连载图的系统。

需要保留的是：

```text
结构化入参
连续故事流水线
锚点图机制
批量生成工具
通用入口配置
情绪推进字段
负面词拆分方法
视觉基因表格式
QA 验收与返工机制
跨会话身份锁定方法
```

需要舍弃的是：

```text
全部人猫角色内容
全部外卖 / 居家故事内容
全部旧项目参考图和母版图
全部旧 IP 专属文案
```
